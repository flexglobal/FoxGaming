# Mono Messenger — Vercel relay (v2)

## Правильный деплой

**На скриншоте пользователя:** `Ready` и `404` одновременно. Ready = Vercel успешно задеплоил то, что получил; 404 означает, что на `/` нет страницы. Если `/api/health` тоже возвращает 404, значит API **не загружен в деплой**.

Для установки: распакуй **отдельный архив Mono_Messenger_Vercel_v2.zip** и размести **его содержимое в корне репозитория** (не вложенный каталог). В корне должны лежать:

```text
api/
  signal.js
  health.js
  news.js
index.html
vercel.json
package.json
```

В Vercel → Project → Settings → Build and Deployment укажи:

- Framework Preset: **Other**
- Root Directory: **./** (если содержимое архива в корне репозитория)
- Build Command: пусто / Override Off
- Output Directory: пусто / Override Off
- Install Command: по умолчанию

Создай **Upstash Redis**. В Vercel → Settings → Environment Variables добавь `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` для Production и redeploy.

### Проверка

1. `https://fox-gaming563gc.vercel.app/` — должно показать страницу «Mono Messenger Relay».
2. `https://fox-gaming563gc.vercel.app/api/health` — JSON `{ "ok": true, "signalingReady": true, ... }` после подключения Redis.
3. `https://fox-gaming563gc.vercel.app/api/signal?id=MONO-AAAAAAAAAAAAAAAAAAAA` — `{ "signal": null }` при пустом почтовом ящике.

Если `/api/health` отвечает `404`, файлы не оказались в правильной корневой директории; перенастрой Root Directory и повторно задеплой. Если `{signalingReady:false}`, проверь переменные Redis. Деплой с одним `vercel.json` или удалённым `vercel.json` не создаёт функции автоматически.

Адрес `https://fox-gaming563gc.vercel.app` уже установлен в новом Messenger по умолчанию. Никаких токенов Redis внутри Mono быть не должно.

## Новостной аккаунт Mono

Официальный аккаунт в Mono — встроенный системный чат с фиксированной отметкой. Он показывает объявления, которые владелец настроенного Vercel-сервера публикует через `/api/news`. Фальшивые новости не генерируются. Объявления **намеренно хранятся в Redis**, в отличие от личных/групповых сообщений.

Добавь в Vercel **серверную** переменную `MONO_NEWS_ADMIN_TOKEN` — случайный секрет длиной минимум 24 символа. Не публикуй его в GitHub и не добавляй в клиент.

Пример публикации из PowerShell (запускается локально владельцем сервера):

```powershell
$secret = Read-Host "Admin token"
$body = @{ title = "Обновление Mono"; body = "Новый выпуск браузера доступен." } | ConvertTo-Json
Invoke-RestMethod -Uri "https://fox-gaming563gc.vercel.app/api/news" -Method Post -Headers @{ Authorization = "Bearer $secret" } -ContentType "application/json; charset=utf-8" -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
```

Это **пример**, он ничего не публикует без запроса владельца и рабочего сервера. В API хранится максимум 30 последних объявлений.

## Соединение и групповые чаты

- SDP-предложения WebRTC временно хранятся в Redis **до 120 секунд** и удаляются после получения; это **не сообщения**.
- Текст, фото, голосовые и файлы передаются WebRTC напрямую; **не записываются на сервере**.
- Создатель группы выбирает контакты (до 8 при создании). Приглашение доставляется только после установления прямого соединения; собеседник должен принять его.
- Для отправки группового сообщения у автора должен быть прямой WebRTC-канал с каждым получателем. Сообщение получают только подключённые участники; если получателей нет, оно не отправляется.
- Контакты, профили и список созданных групп хранятся **локально**. Содержимое сообщений — **только в оперативной памяти** текущего запуска.
- Настоящее WebRTC peer-to-peer соединение может не работать в отдельных сетях без TURN, которого в архиве нет.
- Сервер сигнализации пока **не поддерживает аутентификацию пользователей по ключам**: ID сложно угадать, но он не является доказательством личности. Не используйте эту базовую систему для особо конфиденциальной коммуникации без дополнительной проверки и ключей.

## Разработка

`npm start` внутри папки сервера запускает localhost:8787 с теми же API. Node.js >=20.
